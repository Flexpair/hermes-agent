# flexpair-color-palette

Reference: https://github.com/Flexpair/hermes-plugins.git at `78640444605766af176c202854d66c2d1da64d64`, `flexpair-color-palette/src/plugin.tsx`. Upstream host basis: `3752497cc4d214023f4736559a5f0e58621af9ff`. License copied unchanged from the reference plugin directory. Maintained directly in the Flexpair fork.

Enabled by default. Every enabled registration sets the appearance preference to dark, including a previously saved light preference. Synchronous bundled registration seeds the host's legacy zoom fallback and requests native 150% zoom before page load. Later manual mode and zoom changes remain available until the next activation or app restart; no timer, load listener or zoom notification reasserts the plugin defaults.

Fixed accents follow the painted mode. A plugin-owned persistent restoration baseline survives renderer restarts without disposal; a later non-dark manual preference becomes the next activation's baseline. Each activation broadcasts a plugin-scoped UUID presence request through the existing optional Electron window relay. Previously recorded owners that do not reply within 2 seconds are released; responding peers keep their profile and global baseline. Only owners present at discovery start are candidates, and late replies cannot revive them. The listener remains available to answer other windows until close or disposal, which cancels pending discovery. This is a single bounded handshake, not polling or a timer lease. Suspended or heavily delayed renderers can be falsely treated as closed; without a relay (or when sending fails), owners are conservatively retained and abandoned-owner recovery is unavailable. Renderer reload on the same window/profile replaces the same session-storage UUID slot. Legacy profile-name owners from older baseline records are migrated to synthetic `legacy:<profile>` owners and never expire automatically: their original renderer identity cannot be proven from a UUID reply, so the legacy baseline remains protected until manually cleared.

Disposal and window close restore outstanding assignments only when no remaining owner needs them, preserving later manual edits and unrelated profiles. Window close never writes shared native zoom; explicit disposal resets host-default zoom once. Established SDK routing, including `host.activeConnectionId()` during reconnect, takes precedence over boot hints; only the initial default placeholder uses the pinned `?profile=` or Electron boot profile and saved fallback. The optional existing Electron zoom bridge is not a plugin SDK API; older hosts without it retain appearance behavior. SDK, theme implementation, Electron and plugin loading remain unchanged. These defaults are applied during initialization, not guaranteed before the first native window paint. Unavailable storage or native zoom cannot guarantee 150%.

Official Vite bundled discovery enables fresh defaults; stored explicit disablement takes precedence across restarts and app updates.
